# 上がり始める前にどの項目の点数が上がっているか 検証結果

## 結論

- **合格した項目: すぐ買う場合 「VWAP傾き」・「トレンド」・「EMA整列」・「ギャップ」／15分遅れて買う場合 「トレンド」・「EMA整列」・「ギャップ」**（比べた 20項目のうち）
- すぐ買う場合と15分遅れの場合で、合格した項目は**変わった**（すぐ買うだけで合格: VWAP傾き／15分遅れだけで合格: なし）
- ここでの**先着率**は、買ったあと +2.0% と −0.75% のうち +2.0% に先に届いた割合（判定不能を除いた件数が分母）。**1回平均損益**は、1回買うごとの損益（+2.0%・−0.75%・大引けの損益のいずれか）の平均。**基準**は、同じ買い方で、対象の全判定時点をすべて買った場合の成績
- すぐ買う: 全件を買った場合（基準）の先着率は 14.1%・1回平均損益は +0.045%。総合スコアが前の時点より上がった場面は先着率 13.1%（上がらなかった場面との差 -1.5pt）・1回平均損益 +0.035%。差が最も大きかった項目は「ギャップ」の +9.5pt（前半 +10.8pt・後半 +8.4pt、1回平均損益 +0.076%）
- 15分遅れ: 全件を買った場合（基準）の先着率は 13.4%・1回平均損益は +0.042%。総合スコアが前の時点より上がった場面は先着率 12.8%（上がらなかった場面との差 -0.9pt）・1回平均損益 +0.047%。差が最も大きかった項目は「ギャップ」の +9.7pt（前半 +9.2pt・後半 +10.0pt、1回平均損益 +0.069%）
- ただし合格した項目はすべて、点数が**下がった**場面の先着率も上がった場面と同じか高い（すぐ買うの「VWAP傾き」 上がった 18.8%・下がった 19.7%、すぐ買うの「トレンド」 上がった 19.4%・下がった 22.7%、すぐ買うの「EMA整列」 上がった 19.5%・下がった 22.1%、すぐ買うの「ギャップ」 上がった 23.5%・下がった 26.6%、15分遅れの「トレンド」 上がった 19.8%・下がった 21.0%、15分遅れの「EMA整列」 上がった 19.1%・下がった 19.8%、15分遅れの「ギャップ」 上がった 23.0%・下がった 23.7%）。差が出ているのは「点数が上がったか」ではなく「点数が動いたか」で、これらの項目の点数が動く場面は値動きが大きく +2.0% に届きやすい場面だった、と読むのが自然。上がり始める前の予兆とは言いにくい
- 同じ銘柄を1日に何度も数える偏りを除くため、1日の最初の「上がった」だけを数えると（9章）、上がらなかった組との先着率の差はすぐ買うの「VWAP傾き」 +4.7pt、すぐ買うの「トレンド」 +2.1pt、すぐ買うの「EMA整列」 +2.4pt、すぐ買うの「ギャップ」 +10.0pt、15分遅れの「トレンド」 +3.4pt、15分遅れの「EMA整列」 +2.9pt、15分遅れの「ギャップ」 +9.1pt になる
- 合格した項目の「上がった」組の1回平均損益は +0.069% 〜 +0.156%（基準より +0.027% 〜 +0.114% 高い）。手数料は引いていないため、往復0.1%前後の手数料を引くと -0.031% 〜 +0.056% になる
- 20項目 × 2つの買い方を並べて比べているため、本当は効果が無くても偶然良く見える項目が出やすい。合格した項目があっても、別の期間で確かめ直すまでは売買の判断に使わないこと

- 手数料は引いていない

言葉の意味:

- 判定時点 t: 各営業日の 9:30 から 14:45 までの15分ごとの時刻（昼休みの 11:45・12:00・12:15 を含む22時点）。t より前に終わった15分足（開始時刻が t より前の足）だけを使い、時計を t に固定して `analyzeStock()` を計算する
- 上がった／変わらない／下がった: その項目の点数が、同じ日の t の15分前の時点より大きいか・同じか・小さいか。9:30 は15分前（9:15）が判定時点ではないため比べる相手が無く、対象から外した（9:30 の点数は 9:45 の比べる相手としてだけ使う）。昼休みの 11:45〜12:15 も点数は計算し、次の時点の比べる相手にした（この間は新しい足が無いため、12:00〜12:30 はほとんどが「変わらない」になる）
- すぐ買う: t に始まる15分足の始値で買う。15分遅れ: t の15分後に始まる15分足の始値で買う。どちらも使うシグナルは t の時点のもの。買う足に値段が無い（昼休み・約定なし）判定時点は、その買い方では数えない
- 売り方: 買った足から後の15分足の高値と安値で、買値の +2.0% と −0.75% のどちらに先に届いたかを見る。どちらにも届かなければ大引けで手じまう（その日の日足の終値。無ければ15分足の最後の終値）
- **先着率**: 判定不能を除いた件数のうち、+2.0% に先に届いた割合
- **1回平均損益**: 1回買うごとの損益の平均。+2.0% に先に届けば +2.0%、−0.75% に先に届けば −0.75%、どちらにも届かなければ大引けの値段 ÷ 買値 − 1
- **基準**: 同じ買い方で、対象の全判定時点を（項目で絞らずに）すべて買った場合の成績。項目で選んだ組がこれより良くなければ、その項目で選ぶ意味は無い
- 日ごとの平均: 日ごとに先着率・1回平均損益を出してから、日数で平均した値。件数の多い日に引っぱられにくい
- **リフト**: 先に +2.0% に届いた場面のうち、その項目が t で「上がった」だった割合 ÷ 判定できた全件のうち「上がった」だった割合。1 より大きいほど、値上がりの前にその項目が普段より多く上がっていたことを表す（例: 1.5 なら普段の1.5倍）

合格ライン（買い方ごとに判定）:

1. 「上がった」組の先着率が「上がらなかった」組より 5ポイント以上高い
2. 期間の前半・後半の両方で、「上がった」組の先着率が「上がらなかった」組より高い（1 と同じ向き）
3. 「上がった」組の1回平均損益が基準（全件）を上回る

## 1. 実装前確認の結果

1. analyzeStock の読み込みと先読みの確認: `scripts/thirty-min-check.mjs` は `src/lib/analyze.js` の `analyzeStock` を import し、`api/stock.js` が返す形の payload を組み立てて `api/_scan.js` の `toPriceData()`・`normalizeStock()` を通し、`analyzeStock(stock, pd, null, {})` で呼んでいる。`Date` を差し替えて判定時点に固定し、判定時点より後の15分足・TOPIX・当日以降の日足をでたらめな値に書き換えて計算し直し、結果が変わらないことを抜き取りで確かめている（leakCheck）。今回も同じ仕組みを写して使った（元のファイルは変更していない）。300件を抜き取り、t 以降に始まる15分足（その銘柄と 1306.T）と当日以降の日足を書き換えて計算し直したところ、総合スコア・各項目の点数・TOPIX 前日比が変わった判定時点は 0件
2. 対象銘柄: thirty-min-check.mjs と同じ決め方にできた（前日の出来高上位40＋値上がり率上位20）。thirty-min-check.mjs は実行時の JPX 銘柄一覧と Yahoo の日足で候補を作るが、今回は daytrade-data の日足（JPX 一覧の内国株式 3,716銘柄）で作った。判定に使えた 45日で、延べ 558銘柄が候補になった（1日平均 57.9銘柄）
3. daytrade-data の15分足: リポジトリの外の一時フォルダに読み取り専用で取得して使えた（74日分）。**今回は daytrade-data を使った**（Yahoo の15分足は取り直していない）
4. 1306.T の15分足: daytrade-data には入っていない（JPX 一覧の内国株式だけを保存しているため、ETF は無い）。このため同じ取得元では用意できず、Yahoo から取得した。Yahoo の15分足は直近60営業日分（2026-07-17 〜 2026-10-16）しか返らないが、判定に使う日（助走が揃う 2026-08-10 以降）はすべてこの中に入るため、判定に使える日数は減らなかった。daytrade-data も Yahoo の15分足を保存したものなので、値の作り方は同じ
5. 判定に使える日数: 15分足 74日から助走 29日を差し引いて 45日、そのうち 1306.T の15分足もある日が 45日（25日以上）
6. 呼び出し回数と実行時間: 1日あたり約 58銘柄 × 22時点 × 45日で、見積もりは約 57,000回。事前に1回の計算を測ると約1.2ミリ秒だったため、計算そのものは数分で終わる見込みだった。実際は 55,154回・0.7分（全体 0.9分）

そのほかの確認: 全判定時点で寄り付き後扱いになった（`sessionStarted` が false だった件数 0）。部品の点数の合計はすべて総合スコアと一致した（不一致 0件）

## 10. 注意点

- **週初以外の日の 9:00 の足の欠け（既知の問題）**: daytrade-data の15分足は、週初（その週の最初の取引日）以外の日は 9:00 の足に寄り5分（9:00〜9:04）が入っておらず、前日終値の混入や、その日に付いていない高値・安値が見られる（daytrade-data の `docs/edge-book.md`）。判定時点は 9:30 以降で、買う足も 9:45 以降だが、当日の VWAP・当日の高値と安値・寄り付きレンジ・ギャップなど、当日の 9:00 の足を使う項目の点数と、助走に含まれる過去の日の 9:00 の足を通じて、9:30 以降の計算にも少し影響しうる
- 同じ日の判定時点は相場全体の上げ下げを共有しているため互いに独立ではなく、同じ銘柄も1日に何度も数えている。日ごとの平均（6・7章）と、1日の最初の「上がった」だけの集計（9章）を合わせて見ること
- 20項目 × 2つの買い方を比べているため、偶然良く見える項目が出やすい。期間も 45日と短い
- 15分足の高値・安値だけで判定しているため、同じ足の中の順番は分からない（判定不能として外した）。買値は15分足の始値で、実際に買える値段（売り気配）とは呼値1つぶんずれることがある
- daytrade-data の15分足には 15:30 開始の足（大引けの1点）が入っていないため、大引けでの値動きは +2.0% と −0.75% の判定に入らず、手じまいの値段（日足の終値）にだけ反映される
- TOPIX は連動ETF（1306.T）の値で代用した。本番の立花証券の TOPIX 前日比とは場中の値の取り方が違う可能性がある
- daytrade-data の値段は保存した時点の値で固定されており、後から株式分割などがあっても直らない。分割・併合が疑われる銘柄日は外したが（2章）、比が小さい分割は見逃している可能性がある
- 銘柄群は前日の出来高・値上がり率の上位で、売買が活発な銘柄に偏っている。全銘柄に当てはまるとは限らない
